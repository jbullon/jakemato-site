# MTG Pack Hits

Static GitHub Pages tool at \`/tools/mtg-hits/\`, in Jakemato's existing
cream/green/rounded-card style.

## Product correctness

- **Booster cards:** MTGJSON \`Set.booster[configuration].boosters[].contents\`
  defines which sheets can actually occupy a slot. The corresponding
  \`sheets[*].cards\` lists *print-level UUIDs*, and \`sheets[*].foil\`
  identifies foil/nonfoil eligibility. Source sets are also read so
  Special Guests and supplemental printings can be displayed properly.
- **Product names:** MTGJSON \`sealedProduct\` links physical booster packs
  to their booster configuration. The MH3 \`default\` Play Booster mapping
  is explicitly verified against Wizards' "Collecting Modern Horizons 3."
- **Secret Lair:** only sealed drops with enumerated \`contents.card\` are
  exposed, with each recorded finish. Drops with unspecified contents are
  not treated as verified. Mystery bonus cards are not assumed.
- **Price and image:** exact Scryfall printing ID matched from MTGJSON's
  \`identifiers.scryfallId\`; finish-specific \`usd\`, \`usd_foil\`, or
  \`usd_etched\` must be strictly above $20. The actual printing's image
  and \`purchase_uris.tcgplayer\` are used. Unpriced variants are omitted.
- **Coverage:** paper booster releases from 2024 onward (where source
  sheets and product classifications exist), with MH3 always included,
  plus individually documented Secret Lair drops. It is not an
  exhaustive historical database. Unresolved references are flagged
  on the product rather than silently claimed to be complete.

## Updating

A scheduled GitHub Action runs each day and rebuilds
\`tools/mtg-hits/data/hits.json\` using \`scripts/build_mtg_hits.py\`.
A push to \`master\` that changes the feature also triggers the first
run. The script only replaces the file after fetching the data
successfully; a source outage leaves the previous day's file intact.

To refresh locally:

\`\`\`sh
python -m unittest discover -s tests -p "test_mtg_hits.py" -v
python scripts/build_mtg_hits.py
\`\`\`

No additional Python dependencies or API keys are required. The initial
data file is generated by the first successful workflow run, not hardcoded
from estimates.
